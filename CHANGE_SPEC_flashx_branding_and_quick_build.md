# Change Spec - FlashX Branding and Quick Build (paste questions to create a quiz)

Read this whole file before changing code. This is a change to an existing, working app (self-paced quiz, already merged to `main`). Reuse existing code and patterns. Do not rewrite unrelated parts.

Two features:
1. **Branding:** the app is now called **FlashX by Xcelerator**.
2. **Quick Build:** inside the quiz editor, the admin pastes questions with their correct answers as plain text, and the app turns them into quiz questions. This uses a rule-based text parser written in TypeScript. **No AI, no external API, no API key, no new dependency.**

## Part 2 - Quick Build (paste to quiz)

### 2.1 What the admin experiences (P0)
In the quiz editor, next to "Import from CSV", add a button **"Quick Build"** with a lightning icon. It opens a large panel (full height modal or right drawer) with two columns. On narrow screens the columns stack.

**Left column - input**
- Large textarea: "Paste your questions and answers". Accept text pasted from Word, Google Docs, WhatsApp, PDFs and plain text.
- "Upload .txt or .md" button that loads a file into the textarea.
- "Insert sample" button that fills the textarea with the sample in 2.6.
- A collapsible "Supported formats" guide listing the patterns in 2.3 with short examples.
- Settings: **Default points** (number, default 1). **Mode**: "Add to existing questions" (default) or "Replace all questions".

**Right column - live preview**
- Parse runs in the browser as the admin types (debounced about 300 ms). No server call.
- Summary line: "12 questions found. 10 ready, 2 need fixing."
- One card per question: number, question text, options as rows with the correct one highlighted (tick icon plus colour, never colour alone), points, and the source line number ("from line 14").
- Problems shown on the card:
  - **Blocking** (red): no correct answer, fewer than 2 options, more than 6 options, empty question text, two different answers found.
  - **Notes** (amber, not blocking): options had no labels, answer matched by text, answer taken from answer key, True/False options added automatically.
- Fixing inline on each card: click an option to make it correct, edit question or option text, delete an option, add an option, change points, remove the question.
- A section "Lines we could not read" listing leftover text with line numbers, so nothing is silently dropped.
- Bulk action: "Set all points to N".

**Bottom bar**
- Primary button: "Add 10 questions" (or "Replace with 10 questions" in replace mode, with a confirm dialog that states how many existing questions will be removed).
- Disabled while any question has a blocking problem. Label then reads "Fix 2 questions to continue".
- On confirm, convert to `EditableQuestion[]` with fresh `crypto.randomUUID()` ids and pass them to the editor's existing `updateQuestions`, the same way `ImportModal` does. The existing autosave persists them. No new API route and no database change.
- Keep the pasted text in the panel's state while the panel is open, so closing the confirm dialog does not lose work.

### 2.2 Parser module (P0)
Create `lib/text-import.ts`. Pure TypeScript, no DOM, no dependencies, so it is unit testable and runs in the browser.

```ts
export interface ParsedQuestion {
  sourceNumber: number | null;   // the number written in the text, if any
  line: number;                  // 1-based line where the question starts
  text: string;
  options: string[];
  correctIndex: number | null;
  points: number;
  issues: string[];              // blocking
  notes: string[];               // informational
}
export interface ParseResult {
  questions: ParsedQuestion[];
  unparsed: { line: number; text: string }[];
}
export function parseQuestionText(input: string, opts?: { defaultPoints?: number }): ParseResult;
```

### 2.3 Patterns the parser must handle (P0)

**Clean-up first**
- Normalise line endings, non-breaking spaces, tabs, smart quotes, bullet characters (`•`, `◦`, `▪`, `-` at the start of a line), zero-width characters.
- Remove markdown emphasis (`**x**`, `__x__`) from text, but remember which option was emphasised (see correct answer markers).
- Ignore empty lines except as block separators.

**Question start** (a new question begins at any of these)
- `1.` `1)` `1:` `1 -` `(1)` at the start of a line
- `Q1.` `Q1)` `Q.1` `Q 1:` `Question 1:` `Question 1.` (any case)
- Fallback when there is no numbering at all: blocks separated by blank lines, where each block contains options.
- Text lines after the question line and before the first option are part of the question (multi line questions).

**Options**
- Lettered: `A)` `A.` `A:` `A -` `(A)` `[A]` `a)` `a.` `(a)` for letters A to H (detect beyond F so we can flag "more than 6").
- Roman: `(i)` `i)` `(ii)` ... `(viii)`.
- Several options on one line: `a. Java  b. C  c. Python  d. JavaScript` or `A) 1990 B) 1995 C) 2000 D) 2005`. Only split when the line starts with the first label and the labels appear in sequence (a, b, c ...). Do not split normal sentences.
- Unlabelled options: if a question is followed by 2 to 6 short lines with no labels before the answer line, treat them as options in order and add the note "Options had no labels, check the order".
- True/False: if a question has no options and the answer is True or False (or T/F), create options "True" and "False" and add a note.

**Correct answer** (in order of priority, first match wins, but see conflicts)
1. An answer line right after the options: `Answer: B`, `Ans: b`, `Ans - c`, `Ans.(c)`, `Correct: B`, `Correct answer - B`, `Key: B`, `Solution: B`, `Right answer: B` (any case, any of `:` `-` `.` `=` `)`).
   - The value can be a letter (`B`, `b`, `(b)`, `option b`), a roman numeral, an option number (`2` meaning the second option), or the option text (`Answer: Paris`). For text, match case-insensitively ignoring punctuation and extra spaces; add the note "Answer matched by text".
   - `Answer: B) Paris` - use the letter, and if the text does not match option B, add the blocking issue "Answer letter and text do not match".
2. A marker on an option: `*` or `✓` `✔` `✅` at the start or end, `(correct)` `[correct]` `(ans)` at the end, `<-` or `<--` at the end, or markdown emphasis on exactly one option. Remove the marker from the option text.
3. An answer key section anywhere after the questions: a heading line such as `Answers`, `Answer key`, `Key`, `Solutions`, followed by entries like `1-B`, `1. B`, `1) b`, `Q1: B`, `1 - Paris`, one per line or comma separated on one line (`1-B, 2-C, 3-A`). Match entries to questions by the number written in the text (`sourceNumber`), falling back to order when the questions are not numbered. Add the note "Answer taken from answer key".

**Conflicts and missing answers**
- Two sources disagree (for example a `*` on option A and `Answer: C`): blocking issue "Two different answers found".
- No answer found: blocking issue "No correct answer found - click the right option". **Never guess an answer.**
- Answer points to an option that does not exist (`Answer: E` with 4 options): blocking issue "Answer E does not match any option".

**Points**
- `(2 marks)`, `[2 points]`, `(2 pts)`, `2M` at the end of the question line, or a separate line `Points: 2` / `Marks: 2`. Remove it from the question text. Otherwise use `defaultPoints`. Clamp to 0 to 100.

**Validation of each question** (blocking issues)
- Empty question text.
- Fewer than 2 options or more than 6 options.
- Duplicate option text in the same question (case-insensitive).
- No correct answer or an invalid one.

**Leftovers**
- Any non-empty line that is not used goes into `unparsed` with its line number.

### 2.4 Tests (P0)
Add `tests/text-import.test.ts` with fixture strings covering every pattern in 2.3, at least:
- Numbered questions with `A)` options and `Answer: B`.
- `Q1.` style with lowercase `a.` options and `Ans - c`.
- Inline options on one line.
- Answer by text, including a case and punctuation difference.
- `*` marker and `✓` marker, and the marker removed from the option text.
- Answer key at the end, comma separated and one per line, including questions numbered out of order.
- Unlabelled options with a note.
- True/False with no options.
- Points in brackets and as a separate line.
- Multi line question text.
- Text pasted with Windows line endings, smart quotes and bullets.
- Conflict (marker vs answer line) gives a blocking issue.
- Missing answer gives a blocking issue and `correctIndex` null.
- Seven options gives a blocking issue.
- Unreadable lines appear in `unparsed`.
- A normal sentence containing "a." is not split into options.
- 100 questions parse in under 100 ms.
